# Canonical channel batch and submission status

Deployed 2026-11-28. Channel batches require an authenticated editor via server-managed app_metadata, accept up to 20 valid YouTube IDs, deduplicate and call the canonical reference ingest RPC. `start_processing` defaults true and sets an explicit auto-process flag; false leaves new jobs manual. Existing completed/published data are not reset. Scheduled worker takes one job per run (6,21,36,51 minutes UTC), persists a metadata-only outcome or explicit failure; no automatic editorial release, no fabricated transcript. Submission status accepts exactly one suggestion_id or legacy job_id; uses caller JWT and RLS, with an explicit owner filter for non-editors. Only bounded status fields are returned, not arbitrary job evidence. No legacy submission jobs were present at audit. Tests: duplicate batch, repeated enqueue, real metadata worker and idle replay in rollback; actual service role manual enqueue guard, two distinct suggestion owners verified via RLS; both deployed endpoints return 401 without auth. Positive HTTP user/editor session test and scheduled first nonempty run are still pending. No dummy contributions or jobs persisted, no emails sent. Standalone embedding endpoint remains unresolved: the old tables are absent and the existing embeddings schema must be separately audited.
